## 正確さと確認方法

- 題材は `skills/i-am-visual-thinker/references/copy-and-reference.md`。そこで参照するPythonファイルは現作業ツリーにないため、試作内に教材コードを明示した。存在しないファイルへのリンクや実行観測の主張はしない。
- 数値一つのPythonリストに対象を限定。`a.copy()` は別リスト、`b = a` は同じリストを指す。変更は要素への代入であり、名前の再束縛ではない。
- 図の下で対応するコードを開ける。前後で箱・名前・接続を固定。値の変更は色と文字で示す。左右の箱番号は別の例の識別子であり、左右で共有されない。
- 理解確認は、`b[0] = 2` の後の `a[0] = 7` を予想してから結果を表示する。条件実験室では操作前に変化箇所を予想する。
- `node prototypes/check.cjs` で、コピー・共有・連続操作・同値代入・負数・前状態の保持を確認する。
- `node prototypes/check-browser.cjs` で、WindowsにインストールされたEdgeを使い、入口の3リンク、比較ラボの操作・答え表示・リセット、ステップノートの既読段階の保持、条件実験室の連続操作・同値代入、3案の幅390pxでの横方向のはみ出しを確認する。Node.js 22以降が必要。Edgeが標準パスにない場合は `EDGE_PATH` で指定する。
- `evals/README.md` は現作業ツリーにないため、指定の代表課題・採点基準による評価は未実施。人による理解・所要時間・操作負担の比較も未実施。上の効果は設計仮説であり、検証済みの効果ではない。

試用時は正しい結果を予測できるかに加え、なぜ片方だけ／両方が変わるかを説明してもらう。同じ答えを覚える影響を避け、値や操作順を変えた課題と提示順の入れ替えで比較する。表示の好みと理解の結果を分けて記録する。

## 作業時の確認結果（2026-10-21）

3案に操作起点のアニメーションを追加。書き換える箱の輪郭を強調し、変更値を約1.2秒で切り替える。共有する箱は一つのままで、名前間の値の移動は描かない。同じ値の代入では箱だけを強調する。ステップノートは段階の表示にも短い動きを付ける。再生・停止して結果表示が可能で、OSの「動きを減らす」設定時は静的な結果を即時表示する。

目的は操作対象と変化箇所を追う負担の軽減。静的な差分表示は残し、動きが理解や所要時間を改善するかは今後比較する。演出はPython実行の速度・順序の観測を表さない。保守コストは共通の再生処理と動作検証。動きが読解を妨げる場合は短縮または省略する。

追加後のEdge検証で、3案のアニメーション開始、比較ラボでの停止と再生、3案の動きを減らす設定時の無演出を確認した。教材モデルと既存の操作チェックも成功した。人によるアニメーションの見やすさと理解への効果は未検証。

Node.js v24.14.1で教材モデルのチェック、JavaScript構文確認が成功。Edgeで上記ブラウザ操作とモバイル幅のチェックが成功。図とコードを照合し、箱の共有／分離、更新する対象、操作前後の値が一致することを確認した。利用者の理解評価、実際のキーボード操作・スクリーンリーダーでの確認、他ブラウザでの確認は未実施。
