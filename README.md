# i-am-visual-thinker

プロジェクト内のシステムフローを理解するためのSkill。

コードと仕様を読み、一つの操作・リクエスト・イベントが、どの処理を通り、データや状態をどう変えて、どこで終わるかを説明します。全体の動きを見渡せるアニメーションと、各段階の入力・処理・出力・根拠を行き来できるHTMLを作ります。

## インストール

Node.jsとnpm（npx）が利用できる環境で、導入先のプロジェクトから実行します。

```sh
npx skills add KotaSugiki/i-am-visual-thinker --skill i-am-visual-thinker
```

画面の案内に従って利用するエージェントを選びます。すべてのプロジェクトで使う場合は `-g` を追加します。

インストール前に配布されているSkillを確認できます。

```sh
npx skills add KotaSugiki/i-am-visual-thinker --list
```

オプションの詳細は [Vercel Skills CLIの公式ドキュメント](https://github.com/vercel-labs/skills/blob/main/docs/commands.md#skills-add)を参照してください。

## 何を理解するか

- ある画面操作から、API・データ処理・保存・表示更新までの流れ。
- リクエストが通る認証・検証・分岐と、失敗時に進まない処理。
- イベントやジョブの登録・待機・実行・完了と、応答との関係。

一つの利用場面に絞って調べます。構成や用語の説明は、その流れを理解するために必要な範囲で添えます。対象プロジェクトと関係のない一般概念の教材や、全コードを網羅する図の生成は目的に含めません。

## 説明の体験

1. 対象の入力・開始点・終了点を知る。
2. 全体図を再生し、データの受け渡しや状態変化を追う。
3. 気になる段階を選び、入力・処理・出力と対応コードを見る。
4. 条件を変え、別の経路や止まる場所を予測して確かめる。

全体図と詳細は、現在の経路と段階を保って往復できます。再生・停止・段階送り・任意段階への移動に対応し、止めた図と文章でも読める形にします。段階数は実装に合わせます。

資料から読み取れること、実行で観測したこと、推定、未確認の点を区別します。例えばジョブの登録と完了を別々に示し、確認できない実行順をアニメーションで断定しません。HTMLの再生は説明用で、対象システムの処理を実行するものではありません。

## 依頼の例

- 「このプロジェクトのログイン処理を、送信から画面更新まで追いたい」
- 「注文APIがジョブを登録してから、ワーカーが完了するまでの流れを見たい」
- 「このAPIでキャッシュがある場合とない場合、処理がどこで分かれるか知りたい」

## 試作

[Transformerのアニメーション教材](prototypes/transformer.html)をブラウザで開くと、全体図から各段階の詳細へ進む体験を試せます。[教材の範囲・確認結果](prototypes/transformer-notes.md)も記録しています。これは表現方法を検討した試作で、現在のSkillは対象プロジェクトの実装に根拠を持つフローを扱います。

[比較ラボ・ステップノート・条件実験室](prototypes/index.html)は、以前の概念比較を検討した試作として残しています。

配布時に必要な指示は `skills/i-am-visual-thinker/` 内で完結させ、開発用文書や試作は分けています。構成を変更した後は、ルートでSkillが検出されるかを確認できます。

```sh
npx skills add . --list
```

正確さ、理解への寄与、負担の軽減、扱いやすさ、見た目の順に判断します。生成物の正確さと、人が説明・予測できるようになったかを分けて評価し、特定の認知特性や学習効果を保証しません。
